# 游戏访谈与原型

## 按回答追问

选取当前阶段最影响实现的 1–3 个问题。下列问题用于挑选，也可据回答继续细化。

| 已明确的方向 | 可追问的决定 |
|---|---|
| 游戏想借鉴某个作品 | 最想保留视角、资源循环、建造方式，还是美术氛围？首次试玩只展示其中哪一个能力？ |
| 历史经验参与规则 | 要表现哪个地区、时代、作物与情境？有哪些可核对原文？系统直接显示建议，还是先让玩家观察线索？ |
| 玩家自主选择 | 第一次上手可以做哪两三件事？时间、体力或资源成本哪个最重要？做错后如何看出后果，能否立即重试？ |
| 第二个情境或副本 | 在完成首关、做出正确判断，还是写完笔记时解锁？新关保留哪些条件，只换哪一个变量？ |
| 可编辑田书或经验册 | 用户能改个人注释，还是也要调整试验参数？保存最新一条还是保留历史？刷新、重开、清空时各保留什么？ |
| 要做 3D 或引擎演示 | 谁负责代码、模型、动画和声音？在哪台机器和哪种输入方式展示？哪个玩家必经场景和常用道具优先做精？ |

## 将决定做进小样

1. 用一个能观察、能选择、能看到后果的闭环定义首个样品。涉及农耕决策时，可以用一地、一条可核对资料、两种田况作首版；把地区、物候、天气、地形和作物视作条件，根据体验选择最少变量。古籍规则记录版本与卷次、原文、适用范围、观察线索和建议。结果和阈值按游戏模拟标注，个人记录与原文分别保存。
2. 若需要解锁与复玩，用前后两个可对照情境验证迁移。后一情境改动一个关键条件，让玩家重新判断。选用用户熟悉且能在期限内验证的技术。机制可先用网页或灰盒，确认后再集中制作玩家反复接触的场景、动作与道具。
3. 沿玩家入口测试首关、反馈、第二关与复玩。若有保存，测试编辑、刷新和重置。若要检查文化理解，邀请试用者解释为什么两种情境采取不同做法，按约定记录人数、时间和标准。技术试跑与真实用户反馈分别记录。
